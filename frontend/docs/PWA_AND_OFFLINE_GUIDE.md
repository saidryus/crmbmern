# CRMB Kiosk — PWA & Offline Guide
### What Makes This App Installable and How It Works Without Internet

---

> **Who this is for:** Anyone who wants to understand what a Progressive Web App is, how the CRMB kiosk can be installed on a tablet, and how it keeps working when the WiFi drops.

---

## 📱 What Is a PWA?

**PWA** stands for **Progressive Web App**. It's a website that behaves like a native app — it can be installed on a device, works offline, and feels like it was downloaded from an app store.

Think of it like this:
- A regular website: you open a browser, type a URL, use it, close the browser
- A PWA: you install it once, it appears on your home screen, opens full-screen, works offline

**For a kiosk, this is ideal:**
- Staff can install it on the tablet once
- It opens full-screen with no browser chrome (no address bar, no tabs)
- It works even if the café's WiFi goes down
- No app store needed — no Apple/Google approval process

---

## 🔧 How CRMB Becomes a PWA

Three things make a web app a PWA:

### 1. The Web App Manifest

A JSON file that tells the browser about the app — its name, icon, colors, and how it should display.

**CRMB's manifest (auto-generated by vite-plugin-pwa):**
```json
{
  "name": "CRMB — Artisan Bakery & Café",
  "short_name": "CRMB",
  "description": "Self-service kiosk for CRMB Artisan Bakery & Café",
  "theme_color": "#1e140a",
  "background_color": "#f5efe6",
  "display": "fullscreen",
  "orientation": "portrait",
  "start_url": "/"
}
```

- `display: "fullscreen"` — opens without browser chrome (no address bar)
- `theme_color` — the espresso brown color shown in the device's status bar
- `background_color` — the parchment color shown while the app is loading

### 2. The Service Worker

A **service worker** is a script that runs in the background, separate from the main app. It acts as a middleman between the app and the network.

Think of it like a **local post office**: instead of every letter going directly to the main post office (the internet), the local post office (service worker) keeps copies of frequently-used letters. When you need one, it delivers it instantly from the local copy.

**What CRMB's service worker does:**
- Caches all JavaScript, CSS, and HTML files on first load
- Caches product images from Unsplash (30-day expiry)
- Caches Google Fonts
- Serves cached files when offline

### 3. HTTPS (or localhost)

PWAs require a secure connection. In production, the app must be served over HTTPS. During development, `localhost` is treated as secure.

## 📦 What Gets Cached

The service worker uses different caching strategies for different types of content:

| Content | Strategy | What it means |
|---|---|---|
| JS, CSS, HTML | **Precache** | Downloaded and cached on first install, served from cache always |
| Product images (Unsplash) | **CacheFirst** | Check cache first; if not there, fetch from network and cache it |
| Google Fonts CSS | **StaleWhileRevalidate** | Serve from cache immediately, update cache in background |
| Google Fonts files | **CacheFirst** | Cache for 1 year — fonts don't change |
| Jazz radio streams | **Not cached** | Live streams can't be cached — requires internet |

**CacheFirst** means: "Give me the cached version immediately. I don't care if it's slightly old."

**StaleWhileRevalidate** means: "Give me the cached version now (fast), but also check for updates in the background for next time."

## 📶 How Offline Mode Works

When the device loses internet connection:

```
1. useNetwork() detects navigator.onLine = false
2. window 'offline' event fires
3. OfflineBadge component appears (animated pill at top of screen)
4. Checkout page shows a warning banner
```

**What still works offline:**
- ✅ Browsing the menu (served from cache)
- ✅ Adding items to cart (localStorage)
- ✅ Viewing product details (served from cache)
- ✅ Cart page (localStorage)
- ✅ Admin panel (served from cache)
- ✅ Product management (localStorage)
- ✅ UI sounds (Web Audio API — no files needed)

**What doesn't work offline:**
- ❌ Jazz radio (live stream requires internet)
- ❌ Product images that haven't been cached yet (new images added after install)
- ❌ Checkout (simulated — would need internet for a real payment system)

## 🔄 How Updates Work

When the app code is updated and redeployed:

1. The service worker detects new files are available
2. It downloads the new files in the background
3. On the next page load (or app restart), the new version is used

This is configured with `registerType: 'autoUpdate'` in `vite.config.js` — updates happen automatically without user action.

---

## 🛠️ The PWA Configuration

In `vite.config.js`:

```js
VitePWA({
  registerType: 'autoUpdate',  // auto-update when new version available
  manifest: { ... },           // app metadata
  workbox: {
    globPatterns: ['**/*.{js,css,html,svg,png,ico,woff2}'],  // what to precache
    runtimeCaching: [
      {
        urlPattern: /^https:\/\/images\.unsplash\.com\/.*/i,
        handler: 'CacheFirst',
        options: {
          cacheName: 'unsplash-images',
          expiration: { maxEntries: 60, maxAgeSeconds: 60 * 60 * 24 * 30 }
        }
      },
      // ... Google Fonts caching
    ]
  }
})
```

**Workbox** is the library that powers the service worker. `vite-plugin-pwa` uses Workbox under the hood and generates the service worker file automatically during the build.

## ❓ Common Instructor Questions

**Q: What's the difference between a PWA and a native app?**
A native app is downloaded from an app store and runs directly on the device's operating system. A PWA is a website that uses browser APIs to behave like a native app. PWAs are easier to build and deploy (no app store approval), but have slightly less access to device features.

**Q: What is a service worker exactly?**
A service worker is a JavaScript file that runs in a separate thread from the main app. It can intercept network requests, cache responses, and serve cached content when offline. It's the technology that makes PWAs work offline.

**Q: Why does the app need HTTPS for PWA features?**
Service workers can intercept all network requests, which is a powerful capability. To prevent malicious use, browsers only allow service workers on secure (HTTPS) connections. Localhost is an exception for development.

**Q: What happens to the cache when localStorage is cleared?**
The service worker cache and localStorage are separate storage mechanisms. Clearing localStorage removes cart data, products, and order history. The service worker cache (which stores the app files) is separate and unaffected.

**Q: How much storage does the PWA use?**
The app files (JS, CSS, HTML) are about 500KB. Product images from Unsplash are cached up to 60 images. Google Fonts are cached. Total storage is typically under 10MB — well within browser storage limits.
